网络重连补充：对齐 Web QueryClient 默认 `refetchOnReconnect`，原生从离线恢复时会无视 5 秒/30 秒时间阈值重新验证会话与当前可见功能域。App 在前台则立即刷新；网络在后台恢复时保持 0 请求并只记录一次待刷新，首个 `ON_START` 才消费。Pixel 9 AVD 聊天首页飞行模式前台恢复后模型、会话、风格、用户、知识库五项 GET 全部 200；后台恢复网络时 Launcher 保持前台且目标进程 0 HTTP，重新打开 App 后同五项各请求一次并全部 200。网络可用性使用 Android `INTERNET` 能力而非 Google `VALIDATED`：当前中国网络能稳定访问业务域名，但系统 HTTPS Google 探测持续超时并标成 partial，依赖 `VALIDATED` 会把真实可用网络永久误判为离线。

## 性能验收门槛

- 冷启动：已加入冷启动 Macrobenchmark 与独立 `baselineprofile` 生成模块；官方 Gradle 插件使用非混淆采集变体分别生成启动、长会话滚动、工作区八页导航和 120 帧流式聊天四条关键路径，并经校验后更新所有 R8 变体共享的 24,985 条 Baseline / 18,155 条 Startup 规则。项目、技能、知识库、文件、设置、计费和管理后台主 Compose 方法，以及流式正文分片、O(1) 尾项视图和 ViewModel 事件路径均进入安装时 profile；新增页面没有膨胀 Startup Profile。自定义更新任务也已改为 configuration-cache 兼容的独立 Gradle Task。Pixel 9 AVD 上的临时签名 Release 已真实触发 `ProfileInstaller`，ART `speed-profile` 编译成功，避免原先只有 14 条手写规则且设备输出使用短期 R8 混淆名的问题。同一 Android 17 / 16 KB AVD、同一管理员账号和同一生产后端上以生产 Web → 原生交替顺序复测 10 轮，Web 禁用缓存后的可交互 P50 为 320.7ms，同账号原生 R8 冷启动 P50 为 126.0ms，原生约快 60.7%，且最慢原生样本仍快于最快 Web 样本；待固定真机按同协议留档。
- 首屏：有效登录态优先显示 Room 缓存，再并发刷新用户、模型与会话；进入聊天页后在 IO 线程预取项目、知识库、技能、全部文件、计费和设置六类目标页 payload，合法空结果和 stale 快照均不会重复触发阻塞式加载圈。
- 持久任务：每个 Skill Run 的最后权威快照按账号写入 Room；冷启动或弱网时历史任务卡先显阶段、进度、来源和附件，SSE 同时后台校准。慢缓存只允许填补空状态，绝不覆盖已到达的网络快照；非终态写入以 180ms 合并，终态立即落盘。进度与详情箭头使用原生 spring，移除卡片外层重复尺寸动画，避免 SSE 更新与展开动画叠加布局工作。Pixel 9 AVD 已验证快照落盘、数据库重开读回和跨账号隔离 1/1。
- 任务重组隔离：Skill Run 的 snapshot/loading/mutation/error 已从全局 `LinHubUiState` 拆到独立 `StateFlow`，可见卡片按 runId 做 `distinctUntilChanged` 订阅；进行中快照不再让应用外壳、顶栏、整条信息流、输入框和 Artifact 判断重组，只有完成回执真正 upsert 消息时才更新聊天主状态。JVM 测试与 Pixel 9 Compose 重组计数均证明更新 run-2 不会唤醒 run-1；任务卡交互合并回归 3/3。
- 流式：网络事件完整保留；文本增量按 24ms 合帧提交。流式期间复用稳定可见链，以 O(1) 视图只覆盖最后一条 assistant；分支索引、消息导航条和 Markdown 预热不随 delta 重建，正文按换行边界冻结约 512 字符片段，只重排最后一片。独立 R8 Macrobenchmark 每轮执行 120 次真实 reducer 更新并切换完成态 Markdown，三组各 10 轮全部通过；最终代表 trace 的文本测量/TextLayout 平均开销相对优化前下降约 55%/65%。设备语义树确认完成标记和操作栏位于真实底部、没有残留“生成中”或“回到底部”。AndroidX 原始 P95 仍约 156ms，Perfetto 显示 RenderThread 最长约 211ms 等待模拟器 SurfaceFlinger 释放缓冲区，因此不把 AVD 慢尾部伪报为真机达标。
