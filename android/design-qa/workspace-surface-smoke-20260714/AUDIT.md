# Web 工作区原生页面 Smoke

日期：2026-07-14（Asia/Shanghai）  
设备：Android Studio Pixel 9 AVD `emulator-5554`，Android 17 / API 37  
变体：non-debuggable R8 `benchmark`  
测试：`WorkspaceSurfaceSmokeTest.everyWebWorkspaceSurfaceAndTabIsReachableWithoutNetwork`

## 目的

补齐此前“源码有入口、人工 AVD 验收很多，但页面级自动化较少”的证据缺口。测试使用只在 `BENCHMARK_ENABLED=true` 时可用的确定性工作区，不读取账号、Room 或网络，也不执行订单、兑换、充值、删除等业务写入。

## Fixture

- 管理员用户、一个模型、一个确定性套餐和一个内置回复风格。
- 项目、知识库、技能、文件为空，但均标记为合法已加载状态。
- 设置、计费、管理后台的全部资源标记为已加载；后台系统设置使用默认 `AppSettings`。
- Benchmark 变体的目的地和标签切换只更新 Compose 状态，普通 Debug/Release 继续执行真实加载逻辑。
- JVM 测试锁定管理员角色、全部 loaded resource 集合、套餐、风格和系统设置，防止 fixture 退化成加载失败占位页。

## 自动导航覆盖

共验证 22 个可见原生 surface：

| 功能域 | 自动化入口与可见结果 |
| --- | --- |
| 工作区 | 项目→“还没有项目”；技能→“还没有自定义技能”；知识库→“还没有知识库”；文件→“还没有文件”；新对话→性能测试问候 |
| 设置 | 账户→聊天消息导航条；记忆→“还没有记忆”；回复风格→“自定义风格”；MCP→个人连接器说明 |
| 计费 | 订阅套餐→“自动化套餐”；充值→“余额充值”；用量→“还没有用量记录”；流水→“还没有余额流水” |
| 管理后台 | 供应商、模型与计价、套餐、用户、技能审核、系统设置、全局 MCP、兑换码、用量九个标签及各自唯一内容 |

管理后台横向标签会自动滚动，确保窄屏右侧的系统设置、全局 MCP、兑换码和用量不是只存在于源码而无法触达。

## 结果

- 最终 AVD instrumentation：1 / 1 通过，约 40 秒。
- 目标进程 PID 的测试日志中没有 OkHttp 请求、`FATAL EXCEPTION` 或 `AndroidRuntime` 崩溃。
- 第一轮暴露了抽屉语义先于动画完成出现的触摸竞态；测试现在等待抽屉完全展开后再注入触摸，最终连续通过。
- UiAutomator 使用可见中心坐标触摸，不依赖文本子节点自身是否标记 clickable。
- 2026-07-15 部署后复验首轮在横向后台标签动画期间丢失一次“全局 MCP”点击，目标页面本身用同一 R8 APK 立即重跑 22.195 秒通过。测试现会重新获取同一标签并最多补点一次，但仍必须等待该标签唯一内容出现；正式 Gradle 回归 1/1（32 秒），没有把“标签可见”降级为成功条件。
- 新增计费/后台 MockWebServer 合同层并完成完整 R8 重建后再次回归 1/1（25.337 秒），证明测试依赖没有进入目标 App，也没有改变 22 个页面的可达性。

## 限制

该测试证明主要 Web 页面和标签在原生窄屏上可达、可组合且不会触发网络或崩溃；它不替代真实后端 CRUD、权限、失败恢复、支付或真机兼容性 E2E。对应真实业务证据继续记录在 `DEVICE_E2E_RESULTS.md`。
